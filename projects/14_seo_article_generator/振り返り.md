# 振り返り — Project 14: SEO記事生成ツール

## 発生した課題と解決策

### 1. アウトライン生成でClaudeの応答にコードフェンスが付くことがある
**課題:** `generate_outline()` でJSON形式のレスポンスを期待しているが、Claudeの出力が
```` ```json ... ``` ````のようにコードフェンスで囲まれて返ってくる場合があり、そのまま `json.loads()` するとパースエラーになる。

**解決策:** レスポンスに `` ``` `` が含まれる場合は `split("```")[1]` でコードブロック内側を取り出し、
さらに先頭が `json` で始まっていればその4文字を除去してから `json.loads()` するようにした。

```python
raw = resp.content[0].text.strip()
if "```" in raw:
    raw = raw.split("```")[1]
    if raw.startswith("json"):
        raw = raw[4:]
return json.loads(raw)
```

### 2. 目標文字数の入力値をどう扱うか
**課題:** ユーザーが極端に小さい/大きい目標文字数（例: 10字や100,000字）を入力すると、
Claudeへのプロンプトとしても不適切で、生成結果が崩れる可能性がある。

**解決策:** `/outline` エンドポイント側で `target_chars` を500〜5000の範囲にクランプしてからプロンプトに渡すようにした。
プロンプト内では `約{target_chars:,}文字` のようにカンマ区切りで表示し、Claudeに目安として伝えている。

### 3. アウトラインのセクション数・本文の長さがばらつく
**課題:** Claudeに「目標文字数」だけを伝えても、セクション数や各セクションの分量が安定しない懸念があった。

**解決策:** アウトライン生成プロンプトで「sectionsは5〜7個、各セクションにH3は0〜3個」と明示し、
本文生成プロンプト側でも「導入は200〜300文字」「各H2セクションは200〜400文字」と粒度を指定することで、
目標文字数に近い分量に収まりやすくした。

### 4. Project 13の競合分析結果をそのまま渡すとプロンプトが長くなりすぎる
**課題:** 競合調査結果のテキストは長文になりやすく、そのままアウトライン生成プロンプトに含めるとトークン数が増える。

**解決策:** `competitor_context` を先頭1200文字に切り詰めてからプロンプトに埋め込むようにした
（`competitor_context[:1200]`）。
