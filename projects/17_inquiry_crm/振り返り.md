# 振り返り — Project 17: 問い合わせ管理CRM

## 発生した課題と解決策

### 1. PowerShellからのAPIテストでCSRFトークンエラーになる
**課題:** `Invoke-WebRequest` / `Invoke-RestMethod` で `/api/inquiries` にPOSTすると、
「Bad Request — The CSRF token is missing.」エラーになり、案件登録のテストができなかった。
Flask-WTFのCSRF保護は通常のフォーム送信（`csrf_token()` をhiddenフィールドやmetaタグに埋め込み）を前提としており、
APIへの直接POSTではトークンが付与されないため。

**解決策:** `Invoke-WebRequest -SessionVariable session` でまず `/` にGETしてセッションCookieを取得し、
レスポンスHTMLから `<meta name="csrf-token" content="...">` の値を正規表現で抽出。
それを `X-CSRFToken` ヘッダーに付与し、`-WebSession $session` で以降のPOSTリクエストを送ることでテストできるようにした。

### 2. SQLiteのDBファイルがGit管理に入ってしまう
**課題:** Flask-SQLAlchemyは `sqlite:///inquiries.db` 指定時、デフォルトで `instance/` フォルダを自動作成しその中にDBファイルを置く。
このまま `git add` するとローカルの問い合わせデータがリポジトリにコミットされてしまう。

**解決策:** `.gitignore` に `projects/17_inquiry_crm/instance/` を追加し、DBファイルがGit管理対象に入らないようにした。

### 3. 開発サーバーの停止・後片付けでプロセスが見つからない
**課題:** 動作確認用に起動したFlask開発サーバーを停止しようとしたが、`Get-Process` でプロセス名やパスから
Pythonプロセスを特定する方法では対象プロセスが見つからず、`instance/inquiries.db` やログファイル（`stdout.log`/`stderr.log`）が残り続けた。

**解決策:** `Get-NetTCPConnection -LocalPort 5017` でポート5017を使用しているプロセスのPIDを特定し、
そのPIDを`Stop-Process`で停止。その後、残っていたテスト用DB・ログファイルを削除した。

### 4. ステータス・流入経路の不正値対策
**課題:** ステータス更新やフィルタで、フロントエンドのバグや手動でのAPI呼び出しにより
`STATUSES`/`SOURCES` に存在しない値が送られる可能性がある。

**解決策:** `/api/inquiries/<id>/status` では `status not in STATUSES` の場合は400エラーを返し、
案件登録時の `source` は `SOURCES` に存在しない場合は自動的に「その他」に補正するようにした。
