# ユーザー登録・ログイン付きメモアプリ 要件定義書

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| システム名 | メモアプリ（認証付き） |
| 目的 | 「認証（ユーザー登録・ログイン・パスワードハッシュ化）」と「ユーザーごとのデータ分離」を学ぶための小規模Webアプリを作る |
| 想定利用者 | 開発者本人（学習目的）。将来的には個人用メモツールとしてもそのまま使える |
| 公開URL | http://127.0.0.1:5007 （ローカル動作。今後デプロイ予定） |
| 関連リポジトリ | （新規リポジトリ作成予定） |

## 2. 背景・課題

- これまでのミニプロジェクト（01〜06）は外部API連携が中心で、「ユーザーアカウント」という概念を持つアプリを作っていなかった
- 受託開発でよく求められる「会員登録・ログイン機能」「パスワードの安全な扱い」「ログインユーザーごとのデータ管理」を、小さく簡単なテーマ（メモ）で体験する
- 「新しい技術領域に挑戦 × 小さく数多く作る」の方針に沿って、今回は認証まわりに絞って学ぶ

## 3. 利用シナリオ

**対象**：アプリの利用者本人

**ケース**：日々のちょっとしたメモを、自分専用のスペースに記録・整理したい

1. トップページからユーザー登録（メールアドレス・パスワード）を行う
2. 登録したアカウントでログインする
3. 「新規メモ作成」からタイトルと本文を入力して保存する
4. メモ一覧画面で自分が作成したメモだけが表示される
5. 既存メモの編集・削除を行う
6. ログアウトして別アカウントでログインしても、他人のメモは見えないことを確認する

## 4. 成功指標

| 指標 | 内容 |
| --- | --- |
| 認証フローの実装 | 登録 → ログイン → ログアウトが一通り動作する |
| パスワードの安全性 | パスワードを平文でDB保存せず、ハッシュ化して保存する |
| データ分離 | ユーザーAがユーザーBのメモを閲覧・編集・削除できないことを確認する |
| 学習目標の達成 | Flask-Login・パスワードハッシュ化・DB設計（複数テーブル）の基礎を理解し、次回プロジェクトで再利用できる状態にする |

## 5. 対象範囲（スコープ）

### 5.1 対象に含む
- メールアドレス・パスワードによるユーザー登録
- ログイン／ログアウト
- パスワードのハッシュ化保存（平文保存はしない）
- メモの作成・一覧表示・編集・削除（CRUD）
- メモはログインユーザー本人のものだけが見える・操作できる

### 5.2 対象外（範囲外・将来検討）
- パスワード再設定（メール送信によるリセットフロー）
- ソーシャルログイン（Google/X等の外部認証連携）
- メモの共有・公開機能
- タグ付け・検索・並び替えなどの高度な整理機能

## 7. 運用フロー

```
ユーザー（ブラウザ）
        ↓
Flask（Webアプリ：ルーティング・認証制御）
        ↓
Flask-Login（セッション管理） / Werkzeug（パスワードハッシュ化）
        ↓
SQLite + SQLAlchemy（ユーザー・メモのデータ保存）
        ↓
ユーザー（一覧表示・編集・削除）
```

ポイントは「認証を通った本人だけが、自分のデータにのみアクセスできる」状態を作ること。

## 8. 画面構成（UI）

1. **トップ／ログイン画面**：メールアドレス・パスワード入力欄、ログインボタン、新規登録へのリンク
2. **新規登録画面**：メールアドレス・パスワード（・確認用パスワード）入力欄、登録ボタン
3. **メモ一覧画面**（ログイン後トップ）：自分のメモをカード形式またはテーブル形式で一覧表示、新規作成ボタン、各メモへの編集・削除リンク、ログアウトボタン
4. **メモ作成／編集画面**：タイトル・本文の入力フォーム、保存ボタン

## 9. データ構造（DB設計）

SQLite + SQLAlchemy で以下の2テーブルを管理する。

### usersテーブル

| カラム名 | 型 | 内容 |
| --- | --- | --- |
| id | Integer (PK) | ユーザーID |
| email | String (unique) | メールアドレス（ログインID） |
| password_hash | String | ハッシュ化済みパスワード |
| created_at | DateTime | 登録日時 |

### memosテーブル

| カラム名 | 型 | 内容 |
| --- | --- | --- |
| id | Integer (PK) | メモID |
| user_id | Integer (FK → users.id) | 作成者のユーザーID |
| title | String | メモのタイトル |
| body | Text | メモの本文 |
| created_at | DateTime | 作成日時 |
| updated_at | DateTime | 更新日時 |

## 10. 外部連携・使用技術

| 連携先・ライブラリ | 用途 |
| --- | --- |
| Flask | Webアプリケーションフレームワーク |
| Flask-Login | ログインセッションの管理 |
| Flask-SQLAlchemy | ユーザー・メモデータのORM／DB操作 |
| Werkzeug (generate_password_hash / check_password_hash) | パスワードのハッシュ化・検証 |
| SQLite | アプリ用データベース（ファイルベース、学習・小規模用途向け） |
| shared/csrf_setup.py | 既存共通モジュールを流用しCSRF対策を行う |

## 11. 非機能要件

| 項目 | 内容 |
| --- | --- |
| パフォーマンス | 個人利用規模のため特別な性能要件はなし |
| セキュリティ | パスワードは必ずハッシュ化して保存する／SECRET_KEYは`.env`で管理しリポジトリに含めない／他ユーザーのデータへのアクセスはサーバー側で必ず検証する |
| エラーハンドリング | 登録時のメール重複・パスワード不一致、ログイン失敗時などはメッセージを画面表示する |
| CSRF対策 | `shared/csrf_setup.py` による共通CSRFトークン検証を導入する |

## 12. 制約事項・前提条件

- 学習目的のミニプロジェクトのため、まずはローカル動作を優先し、動作確認後にデプロイを検討する
- DBはまずSQLite（ファイル1つで完結）を使用し、本番運用を見据えた高度なDB設計は今回のスコープ外とする
- 「型」に沿って 要件定義 → 実装 → デプロイ → README → 振り返りメモ の順で進める

## 振り返り用メモ欄（実装後に記入）

- 今回詰まった点：
  - フォームの POST に CSRF トークンの隠しフィールドが必要なことを見落とし、最初は全フォームが 400 エラーになっていた（`<meta>` タグだけでは不十分で、`<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` をフォーム内に追加する必要がある）
  - Render デプロイ後に「Not Found」が出たが、ローリングリスタート中のタイミング問題であり、安定後は正常動作した。`POST /register → 302` がログで確認できていたため登録自体は成功していた
- 次回試したいこと：
  - パスワード再設定フロー（メール送信 → リセットリンク）をメール送信ライブラリ（Flask-Mail 等）で実装してみる
  - SQLite を PostgreSQL（Render の無料マネージド DB）に切り替えてデータを永続化する
  - pytest でログイン・登録・アクセス制御の自動テストを書く（スプリント #7「テスト付き API」の予習）
