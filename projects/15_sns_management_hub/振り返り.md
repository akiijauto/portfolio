# 振り返り — Project 15: SNS統合管理ツール

## 発生した課題と解決策

### 1. Notion未連携でもエラーにせず動かしたい
**課題:** このツール単体でも使えるようにしたいが、`NOTION_TOKEN` や `NOTION_DATABASE_ID` が
未設定の環境では `/calendar` がエラーになってしまうと、カレンダー機能を使わないユーザーにとって不親切。

**解決策:** `get_notion()` で `NOTION_TOKEN` が無い場合は `None` を返すようにし、`/calendar` 側で
`notion` または `db_id` が無ければ `{"ok": True, "posts": [], "warning": "Notion未設定"}` を返すようにした。
正常系のレスポンス形式（`ok: True`）を維持したまま警告だけを表示できる。

### 2. Notion APIの取得失敗時にアプリ全体を落とさない
**課題:** Notion DBのスキーマ変更やAPIエラーで `databases.query` が例外を投げると、カレンダー表示全体が機能しなくなる。

**解決策:** `fetch_calendar()` 内で `try/except` を行い、失敗時は警告ログを出して空リスト `[]` を返すようにした。
呼び出し側（`/calendar`）はこれをそのまま正常系として扱える。

### 3. SNSごとにハッシュタグの慣習・文字数上限が大きく異なる
**課題:** Instagram（最大30個）・Twitter（2〜5個）・LINE（0〜2個）でハッシュタグの最適個数が大きく異なり、
投稿文の文字数上限も Instagram 2200字・Twitter 140字・LINE 500字と差がある。
単一のプロンプトで一律に生成すると、SNSごとの実態に合わない結果になりやすい。

**解決策:** `SNS_HASHTAG_RULES`（最大個数・傾向の説明）と文字数上限の辞書をSNS種別ごとに用意し、
プロンプトに動的に埋め込むことで、SNSごとの慣習に沿った生成結果になるようにした。

### 4. Claudeの応答にコードフェンスが付く問題
**課題:** Project 13・14と同様、`generate_hashtags()` / `generate_variations()` でJSON形式を期待しているが、
Claudeの出力が`` ```json ``` ``で囲まれて返ってくることがある。

**解決策:** Project 13・14と同じパターンで、`` ``` `` を含む場合は `split("```")[1]` でコードブロック内側を取り出し、
先頭が `json` であれば除去してから `json.loads()` するようにした。

### 5. 「②バリエーション生成」で「AI(Claude)の処理中にエラーが発生しました」が頻発する
**課題:** 本番で「カフェメニュー10選」×Instagram×「テンション高め・エネルギッシュ」などの組み合わせで
`/variations` が500エラーになることが繰り返し発生した。本番ログを確認すると、原因は
`generator.generate_variations()` 内の `json.loads(raw)` が
`json.decoder.JSONDecodeError: Unterminated string starting at: ...` で失敗していたこと。

`generate_variations()` は当初 `max_tokens=1500` でClaudeを呼び出していたが、Instagramは
1投稿あたり最大2200文字を許容しており、3案分の絵文字混じり日本語JSONを生成すると
1500トークンを超えて応答が途中で切れてしまい、不完全なJSON（文字列が閉じられていない）になっていた。

さらに、`max_tokens` を十分に増やして応答が完全に終わっても（`stop_reason: "end_turn"`）、
絵文字や改行を多く含む長文をJSON文字列として埋め込む際に、Claudeがまれに区切りの`,`を
落とすなど構文的に不正なJSONを返すケースがあることも実際の検証で確認できた。

**解決策:**
1. `generate_variations()` の `max_tokens` を 1500 → 8192 に拡大し、3案分の長文JSONが
   途中で切れる可能性を大きく減らした。同様のパターンを持つ `generate_hashtags()`
   （Project 15）、`generate_all()`（Project 16）、`generate_outline()`（Project 14）の
   `max_tokens` も合わせて見直した。
2. `_create_json()` という共通ヘルパーを各generator.py内に追加し、`json.loads()` が
   `JSONDecodeError` で失敗した場合は最大2回まで自動リトライするようにした
   （`max_tokens` を増やしても発生しうる、構文エラー由来のまれな失敗に対応）。

**学び:** 「AI(Claude)の処理中にエラー」という同じ表示文言でも、原因は呼び出しごとに異なる
（Project 13では検索のConnectTimeout、Project 15ではJSONの途中切断・構文エラー）。
本番ログのトレースバックを必ず確認し、`json.decoder.JSONDecodeError` であれば
「Claudeの応答が長すぎてmax_tokensで切れていないか」「絵文字・改行を含む長文をJSON化させていないか」
をまず疑うとよい。同種のJSON出力パターンを持つ他プロジェクトも横断的に確認し、
予防的に同じ修正を適用した。

### 6. ①②③が独立した機能のままで、選んだ内容をまとめて予約投稿にできない
**課題:** ①でハッシュタグを選んでも、②で投稿文を生成しても、それぞれコピーするだけで終わっており、
③の投稿カレンダーへ反映するには手動でNotionを操作する必要があった。3つの機能が連携していなかった。

**解決策:**
- ②の各バリエーションカード（`.var-card`）をクリックで1案選択できるようにし（`selected`クラスでハイライト）、
  選択状態は `window._selectedVarIdx` で管理する
- ①のハッシュタグは既存の `.ht-chip[data-sel="1"]` の選択状態をそのまま再利用
- Project 06の `save_to_notion` と同じNotion DBプロパティ構成（`名前`/`SNS種別`/`投稿文`/`状態`=下書き/`作成日`/`投稿日時`）で
  `generator.save_to_calendar()` を新設し、選択した投稿文＋ハッシュタグを結合して保存する `/save_to_calendar` を追加
- 保存後は③タブの更新ボタンで同じNotion DBから確認できる（Project 06が書き込み、Project 15が読み込みも書き込みも行える形に）

**学び:** 各タブの「選択状態」をDOM上のクラス/属性（`data-sel`, `.selected`）で持たせておくと、
別タブの保存処理から横断的に参照できるため、専用のグローバル状態管理を増やさずに機能連携できた。

### 7. Project 01・06・15の機能重複を解消し、1ツールに統合
**課題:** Project 01（SNS投稿文自動生成ツール）・Project 06（SNS半自動運用システム）・Project 15（SNS運用管理ハブ）は
「テーマ提案→投稿文生成→ハッシュタグ→カレンダー予約→投稿→効果分析」という一連の運用フローが3ツールに分散しており、
投稿文生成やNotion投稿カレンダーなど機能も重複していた。利用者がいなかったため、移行リスクを抑えつつ統合する好機と判断した。

**解決策:**
- Project 15を母艦として、Project 06の`planner.py`から`suggest_topics`（テーマ提案）・`generate_image_prompt`（画像プロンプト生成、選択済み投稿文ベースに変更）・
  `engagement.py`（SQLiteによる効果分析）を、Project 01の`web_app.py`から`fetch_all_posts`・`update_status`・`update_schedule`・`edit_post`・
  `cancel_schedule`・`delete_post`・Discord通知（`notifier.py`）を移植し、`generator.py`に統合
- UIを5タブ構成（①テーマ提案 ②ハッシュタグ最適化 ③投稿文生成・画像プロンプト ④投稿カレンダー ⑤効果分析）に再編
- Project 01の予約投稿チェックには「Twitter/Instagramを実際には投稿せず`投稿済み`にしてしまう」スタブ的な不具合があったため、
  統合時にTwitterは認証情報があれば`tweepy`で実際に自動投稿し、なければDiscordへ手動投稿を促す通知に変更して修正
- `render.yaml`から`sns-auto-system`サービス定義を削除し、`sns-management-hub`にDiscord/Twitter用の環境変数を追加
- `projects/01_sns_post_tool`・`projects/06_sns_auto_system`は`git rm`で削除し、`portal.html`のカードも整理

**学び:** 「ユーザーがいない」状態は、機能重複した複数ツールを1本に統合する絶好のタイミング。
個別に育った3ツールのコードを見比べると、同じ目的の処理（Notion予約投稿の状態更新など）が
微妙に異なる実装・粒度で複数存在していることが分かり、統合時にバグ（投稿済み誤マークなど）も同時に発見・修正できた。
