# 要件定義 — Project 15: SNS統合管理ツール

## 概要

SNS投稿運用の全フロー「テーマ提案 → ハッシュタグ最適化 → 投稿文生成・画像プロンプト → 投稿カレンダー（承認・予約・自動投稿） → 効果分析」を
1つのツールにまとめたオールインワンSNS管理ツール。
旧Project 01（SNS投稿文自動生成ツール）・旧Project 06（SNS半自動運用システム）の機能をすべて統合し、両プロジェクトは廃止した。

## 機能要件

### ① テーマ提案
- 業界・ジャンル・ターゲット・提案数（1〜50）を入力
- Claudeが投稿テーマ候補をJSON配列で提案
- ⑤効果分析で記録されたエンゲージメントの高いトピック（`engagement.hot_topics`）には🔥バッジを表示
- 提案テーマをクリックすると③投稿文生成のテーマ欄に反映され、タブが切り替わる

### ② ハッシュタグ最適化
- 投稿テーマ・SNS種別（Instagram/Twitter/LINE）・業界/ジャンル（任意）を入力
- SNSごとのハッシュタグ慣習（最大個数・傾向）に沿ったハッシュタグセットと選定戦略をClaudeが生成
- 生成結果はタグのグリッド表示＋プレーンテキストでコピー可能。タグはクリックで選択トグル

### ③ 投稿文生成・画像プロンプト
- 投稿テーマ・SNS種別・文体トーンを入力
- 「問題提起型」「メリット提示型」「ストーリー型」の3つの切り口で、SNSごとの文字数上限に収まる投稿文をClaudeが生成
- 3案から1つを選択（クリックでハイライト）し、「🎨画像プロンプトを生成」でMidjourney/DALL-E向け英語プロンプト（50words以内）を生成
- 選択した投稿文＋②で選択中のハッシュタグ＋投稿日時（任意）を投稿カレンダー（Notion DB）へ「下書き」状態で保存可能

### ④ 投稿カレンダー
- Notion DBから状態を問わず全投稿を取得し、予約日時・SNS種別・タイトル・本文・状態を一覧表示
- ステータスに応じた操作ボタンを表示:
  - 下書き: 日時指定して「承認して予約」（`/schedule_post`）
  - 承認済み: 「予約更新」（`/edit_schedule`）、「予約取消」（`/cancel_schedule`）、「Discordへ投稿」（`/post_discord`）、SNS種別がTwitterの場合は「Twitterへ投稿」（`/post_twitter`）
  - 全状態: 「削除」（`/delete`、Notionページをアーカイブ）
- Notion未設定時は警告表示のみで空一覧を返す

### ⑤ 効果分析
- 投稿後のいいね・コメント・リーチ数を記録（`/engage`、SQLite `engagement.db`）
- トピック別の投稿数・平均いいね/コメント/リーチ・スコアをランキング表示（`/analytics`）
- 投稿カレンダーの全投稿本文からハッシュタグを抽出し、利用頻度TOP30を表示（`/hashtag_ranking`）

### バックグラウンド処理（APScheduler）
- `check_scheduled_posts`（1分間隔）: 承認済みかつ投稿日時を過ぎた投稿を処理
  - LINE: Discordへ通知し「投稿済み」に更新
  - Twitter: Twitter API認証情報があれば`tweepy`で自動投稿し「投稿済み」に更新。なければDiscordへ「手動投稿が必要」通知
  - Instagram等: Discordへ「手動投稿が必要」通知のみ（状態は変更しない）
- `check_reminder`（1分間隔）: 投稿予定13〜15分前の承認済み投稿をDiscordへリマインド通知

## データ構造・API

| ルート | メソッド | 説明 |
| --- | --- | --- |
| `/` | GET | メイン画面（5タブ切り替えUI） |
| `/suggest` | POST | テーマ提案（`industry`, `target`, `count`） |
| `/hashtags` | POST | ハッシュタグ生成（`topic`, `sns_type`, `industry`） |
| `/variations` | POST | バリエーション生成（`topic`, `sns_type`, `tone`） |
| `/image_prompt` | POST | 画像プロンプト生成（`post_text`, `sns_type`） |
| `/save_to_calendar` | POST | 選択したバリエーション＋ハッシュタグを投稿カレンダーに保存（`topic`, `sns_type`, `post_text`, `hashtags`, `scheduled_at`） |
| `/calendar` | GET | Notion DBから予約投稿一覧を取得（既存互換） |
| `/posts` | GET | Notion DBから全投稿を取得（状態問わず、カレンダー管理用） |
| `/approve/<page_id>` | POST | 状態を「承認済み」に更新 |
| `/schedule_post/<page_id>` | POST | 予約日時を設定し「承認済み」に更新（`scheduled_at`） |
| `/edit_schedule/<page_id>` | POST | 予約日時・本文を編集（`scheduled_at`, `content`） |
| `/cancel_schedule/<page_id>` | POST | 予約を取消し「下書き」に戻す |
| `/post_discord/<page_id>` | POST | Discordへ投稿通知し「投稿済み」に更新 |
| `/post_twitter/<page_id>` | POST | Twitterへ自動投稿し「投稿済み」に更新 |
| `/delete/<page_id>` | POST | 投稿をアーカイブ（削除） |
| `/engage` | POST | エンゲージメント記録（`topic`, `sns_type`, `likes`, `comments`, `reach`） |
| `/analytics` | GET | トピック別人気度ランキングを取得 |
| `/hashtag_ranking` | GET | ハッシュタグ利用頻度TOP30を取得 |

テーマ提案レスポンス例:
```json
{"ok": true, "topics": ["テーマ1", "テーマ2", ...], "hot": ["テーマ1"]}
```

ハッシュタグ生成レスポンス例:
```json
{"hashtags": ["#タグ1", "#タグ2"], "strategy": "選定戦略の説明"}
```

バリエーション生成レスポンス例:
```json
[{"angle": "問題提起型", "post": "投稿文1"}, ...]
```

## 画面構成（タブ）

1. **①テーマ提案** — 業界/ターゲット/提案数入力 → テーマ一覧（🔥人気バッジ付き、クリックで③へ反映）
2. **②ハッシュタグ最適化** — テーマ/SNS/業界入力 → ハッシュタググリッド＋戦略説明
3. **③投稿文生成** — テーマ/SNS/トーン入力 → 3切り口の投稿文カード＋画像プロンプト生成＋投稿カレンダー保存
4. **④投稿カレンダー** — 全投稿の一覧テーブル（状態別操作ボタン付き）
5. **⑤効果分析** — エンゲージメント記録フォーム＋人気トピックランキング＋ハッシュタグ利用ランキング

## 技術スタック

- Flask + Flask-WTF（CSRF）+ APScheduler
- Anthropic Claude API（claude-haiku-4-5） — テーマ提案・ハッシュタグ生成・バリエーション生成・画像プロンプト生成
- Notion API（`notion_client`） — 投稿カレンダーDB
- Discord Webhook（`requests`） — 投稿通知・リマインド
- Twitter API（`tweepy`） — 自動投稿
- SQLite — 効果分析データ（`engagement.db`）
- 共通: `shared/csrf_setup.py`, `shared/errors.py`, `shared/utils.py`, `static/base.css`

## 成功条件

1. 業界・ターゲットを入力すると、AIが投稿テーマ候補を提案する
2. テーマを入力すると、SNSごとのルールに沿ったハッシュタグセットと戦略説明が生成される
3. 同じテーマで3つの切り口の投稿文バリエーションが生成され、選択した投稿文から画像プロンプトを生成できる
4. 選択した投稿文＋ハッシュタグを投稿カレンダー（Notion DB）に「下書き」として保存できる
5. 投稿カレンダーで投稿の承認・予約・編集・取消・削除、Discord/Twitterへの投稿ができる
6. 予約時刻になった投稿はAPSchedulerが自動投稿またはリマインド通知する
7. 投稿後のエンゲージメントを記録し、人気トピック・ハッシュタグのランキングを確認できる
8. Anthropicのクレジット残高不足エラー時は、利用者に「一時的にサービス提供を中断している」旨を表示し、管理者へ自動通知する
9. ローカル起動 `python app.py` → ポート 5015 で動作
