# 振り返り — Project 21: 写真ベース 衛生点検・HACCP記録サポート

## 発生した課題と解決策

### 1. 画像をClaude APIにどう渡すか
**課題:** これまでのプロジェクトはテキストのみのプロンプトだったが、本プロジェクトでは
ユーザーがアップロードした写真をClaudeに解析させる必要があり、`shared/utils.py`の
`call_claude_json()`はテキストのみのmessages構造を前提としていて使えない。

**解決策:** Flaskで`request.files`から画像を受け取り、base64エンコードして
`messages`の`content`配列に`{"type": "image", "source": {"type": "base64", "media_type": ..., "data": ...}}`
として渡す形式に変更。JSON抽出は既存の`extract_json()`を再利用し、一時的なAPIエラーのリトライは
`TRANSIENT_ANTHROPIC_ERRORS`を使って`call_claude_json`と同等のロジックを`generator.py`内に実装した。

### 2. AIが写真から判断できない内容を断定してしまうリスク
**課題:** 暗い写真・ピントが合っていない写真などでは、温度表示や清掃状況が実際には見えないにも
かかわらず、AIが「OK」「NG」などと断定してしまうと、誤った点検記録になりかねない。

**解決策:** プロンプトで「判断できない項目は無理に断定せず『確認不可』とする」ことを明示し、
JSON出力のresultに「確認不可」を選択肢として含めた。実際にテスト用の暗い画像でテストした際も、
「写真が暗く詳細な確認ができません」という適切な「確認不可」judgementが返ることを確認した。

### 3. 画像アップロードとCSRF保護の両立
**課題:** これまでのプロジェクトは`fetch()`でJSONボディを送信していたが、画像ファイルは
`FormData`（multipart/form-data）で送信する必要があり、Content-Typeをブラウザに自動設定させる
必要がある（JSONヘッダーを固定するとマルチパートが壊れる）。

**解決策:** フロント側では`Content-Type`ヘッダーを指定せず`X-CSRFToken`ヘッダーのみを設定して
`FormData`を送信する形に統一。`shared/csrf_setup.py`のCSRF検証はヘッダーのみを見るため、
multipart送信でも問題なく機能することを確認した。

### 4. 点検記録の永続化方針
**課題:** HACCP点検記録は本来日次で記録・保存すべきものだが、本プロジェクトをDB永続化すると
他プロジェクトとの一貫性（ステートレス設計）が崩れ、構成が複雑になる。

**解決策:** ポートフォリオ上のデモとしては「その場で点検結果を確認し、必要なら記録としてまとめて
ダウンロードできる」ことが要件として十分なため、点検記録はフロントエンドのJS配列（`_log`）に
保持し、ページを離れると消える設計とした。「②本日の点検記録」からテキストファイルへの
ダウンロード機能を用意することで、必要な記録はその場で保存できるようにしている。
