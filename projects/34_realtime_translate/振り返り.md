# 振り返り — Project 34: 多言語リアルタイム翻訳チャット

## 発生した課題と解決策

### 1. ブラウザ側でSSEをfetch+ReadableStreamで受信する
SSEの標準APIである`EventSource`はGETリクエストしか送れないため、POSTで本文
（翻訳したいテキスト）を送りたい本アプリでは使えなかった。代わりに`fetch()`で
POSTし、`response.body.getReader()`でストリームを直接読み、`\n\n`区切りで
`event: ...` / `data: ...`形式のSSEメッセージを自前でパースする実装にした。
Flask側は`Response(generate(), mimetype="text/event-stream")`で
`event:`/`data:`形式の文字列をそのままyieldするだけで、特別なライブラリは不要だった。

### 2. Flask開発サーバーでのストリーミング動作確認
`flask run`や`app.run()`のデフォルト（シングルスレッド）では、ジェネレータからの
yieldが正しくチャンクごとに送出されないことがあるため、`app.run(threaded=True)`を
明示的に指定した。本番のgunicornでも`--worker-class gthread --threads 4`を指定し、
SSEのストリーミングが1リクエストでワーカーを占有して他のリクエストをブロックしない
ようにした。

### 3. テストで生成器（ジェネレータ）ベースのレスポンスを確実に消費する
pytestでFlaskのtest_clientを使う場合、`Response(generate(), ...)`のような
ジェネレータベースのレスポンスは、`response.data`または`get_data()`を呼ぶまで
中身が実際には実行されない（遅延評価）。これに気づかず「DB保存まで完了している」
前提でテストを書いたところ、履歴が0件のまま失敗した。`res.get_data()`を呼んで
ジェネレータを最後まで消費させることで解決した。
