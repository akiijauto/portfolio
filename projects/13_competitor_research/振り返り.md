# 振り返り — Project 13: 競合調査ツール

## 発生した課題と解決策

### 1. DuckDuckGo検索結果が0件になる
**課題:** `a.result__a` のリンクから `href` をそのまま取得すると、実URLではなく
`//duckduckgo.com/l/?uddg=<エンコード済みURL>&rut=...` というDDGのリダイレクトラッパーURLが返ってくるため、
「`http`から始まり`duckduckgo.com`を含まない」という単純なフィルタでは0件になってしまった。

**解決策:** `urlparse(href).query` を `parse_qs` でパースし、`uddg` パラメータをデコードして実URLを取り出すようにした。

```python
if "uddg=" in href:
    qs = parse_qs(urlparse(href).query)
    real = qs.get("uddg", [""])[0]
    if real.startswith("http") and "duckduckgo.com" not in real:
        urls.append(real)
```

### 2. 広告（スポンサーリンク）のURLが結果に混入する
**課題:** `uddg` をデコードした結果の中に `duckduckgo.com/y.js?ad_domain=...` のような広告用URLが含まれることがあった。

**解決策:** デコード後のURL `real` に対しても `"duckduckgo.com" not in real` のチェックを行い、広告URLを除外した。

### 3. スクレイピング結果の日本語タイトルがPowerShellで文字化けする
**課題:** テストスクリプトの実行結果をPowerShellで確認したところ、日本語タイトルが文字化けして見え、
スクレイピング自体に問題があるのではと疑った。

**解決策:** `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")` を使ってテストスクリプトの標準出力を
UTF-8に固定して再実行したところ、正しい日本語タイトル（例:「Python & Flask 入門チュートリアル① #自分用 - Qiita」）が
表示された。原因はスクレイピングではなく、Windows PowerShellのコンソールエンコーディング（cp932）による表示上の問題であり、
Flaskが返すJSONレスポンス自体には影響がないことを確認した。

### 4. スクレイピング先のエンコーディング誤検出
**課題:** 一部サイトで `resp.encoding` が `iso-8859-1` などの不正確な値になり、文字化けする可能性があった。

**解決策:** `resp.encoding` が未設定または `iso-8859-1` / `windows-1252` の場合に `resp.apparent_encoding` を使うようフォールバックを追加した。

### 5. 本番(Render)で「①キーワード検索」が常に失敗する
**課題:** ローカルでは`search_competitors`が正常に動作するのに、Render上では「AI(Claude)の処理中にエラーが発生しました」と表示され検索が失敗した。
Render本番ログを確認すると、実際は`/search`内の`requests.get("https://html.duckduckgo.com/html/")`が
`ConnectTimeout`（15秒）で例外を投げており、Claudeには到達していなかった。`html.duckduckgo.com`は
`lite.duckduckgo.com`・`duckduckgo.com`と同一のAzure IP(`20.43.161.105`)に解決され、
このIPがRenderなどクラウド事業者のデータセンターIPからの接続をブロック（パケット無応答）していると考えられる。

**解決策:**
1. `/search`の汎用エラーメッセージを、Claudeとは無関係な`err("ai_error")`から`err("fetch_failed")`（「ページの取得に失敗しました」）に修正し、原因の切り分けをしやすくした。
2. `TAVILY_API_KEY`が設定されている場合はTavily Search API（`https://api.tavily.com/search`、月1,000件まで無料・カード不要）を優先的に使用し、未設定時のみDuckDuckGoにフォールバックする`_search_tavily`/`_search_duckduckgo`の二段構成に変更した。Renderの環境変数に`TAVILY_API_KEY`を設定することで本番でも安定して検索できるようにした。

**学び:** 「AI(Claude)の処理中にエラー」という表示文言だけでは、実際にClaudeが呼ばれているかどうかは判断できない。
ローカルで再現しない本番エラーは、まず本番ログのトレースバックでどの行の例外かを確認するのが最短経路だった。
また、スクレイピング対象が同一IP/CDNに集約されている場合、別サブドメインへの切り替えは回避策にならない。
