# 振り返り — Project 18: 補助金・助成金マッチング＋事業計画ドラフト生成

## 発生した課題と解決策

### 1. jGrants APIのレスポンスが文字化けする
**課題:** jGrants公開APIに `requests.get()` でアクセスすると、JSONレスポンスのテキスト項目
（タイトル・対象エリアなど）が文字化けして取得される。レスポンスヘッダにcharset指定がなく、
requestsが誤った文字コードでデコードしてしまうため。

**解決策:** `resp.encoding = "utf-8"` を `resp.json()` 呼び出し前に明示的に設定することで解決。
`jgrants_api.py` の検索・詳細取得の両関数に適用済み。

### 2. 補助金詳細のdetailフィールドがHTML形式で扱いにくい
**課題:** jGrants詳細APIの `detail` フィールドはリッチテキスト（HTML）で返ってくるため、
そのままClaudeへのプロンプトに渡すとタグだらけで読みにくく、トークンも無駄に消費する。

**解決策:** `BeautifulSoup(detail_html, "lxml").get_text("\n")` でプレーンテキストに変換し、
4000文字でトルケートしてからプロンプトに渡すようにした。

### 3. 既存4プロジェクト（02/14/16/17）のステートレス／永続化パターンとの位置づけ
**課題:** 本プロジェクトは外部API（jGrants）からのデータ取得が必須で、検索結果はリクエストごとに変動する。
案件CRM（17）のようにDB永続化すべきか検討した。

**解決策:** ポートフォリオ上は「検索→診断→ドラフト生成」の一連のフローを1セッション内で完結させれば十分なため、
DBを持たないステートレスな構成のまま、フロントエンドのJS変数（`_selectedSubsidy`等）で
タブ間の状態（選択中の補助金・引き継いだ事業内容）を共有する設計とした。

### 4. 適合判定と事業計画ドラフトでのプロンプト設計
**課題:** Claudeに「適合度スコア」を出させる際、診断の根拠（reasons）と懸念点（concerns）を
混在させると、申請者が「やるべきこと」を判断しづらい。

**解決策:** JSON出力のフィールドを `reasons`（適合理由）/ `concerns`（注意点）/
`required_documents`（必要書類の推定）/ `next_action`（次のアクション）に分割し、
画面側でも見出しを分けて表示することで、診断結果から次の行動までを一目で把握できるようにした。
