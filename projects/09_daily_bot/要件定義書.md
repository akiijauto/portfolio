# 毎朝Discordお知らせbot 要件定義書

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| システム名 | 毎朝Discordお知らせbot |
| 目的 | 「APSchedulerによる定期実行・Flaskとバックグラウンドスレッドの共存」を学ぶ学習用ミニプロジェクト |
| 想定利用者 | 開発者本人。朝の情報収集を自動化したい個人 |
| 公開URL | http://127.0.0.1:5009（ローカル動作。今後Renderデプロイ予定） |
| 関連リポジトリ | 既存リポジトリ akiijauto/sns-auto-post に追加 |

## 2. 背景・課題

- スプリント#1（認証）・#2（外部API）と来て、次の実務頻出パターンは「定期実行」
- APSchedulerは既に requirements.txt に含まれているが、Flaskと組み合わせる方法・cronトリガーの設定・バックグラウンドスレッドとのデータ共有を体験していない
- スプリント#2で作った fetchers.py（天気・為替・ニュース）を再利用することで「部品を組み合わせて新機能を作る」経験も得られる

## 3. 利用シナリオ

**ケース**：毎朝 Discord に今日の天気・為替・ニュース要約を自動で届けたい

1. Webブラウザでアプリを開き、配信時刻（例：08:00 JST）を設定して「スケジュール保存」
2. 指定時刻になると自動で天気・為替・ニュースを取得し、Discordの指定チャンネルに投稿
3. 「今すぐ送信」ボタンで任意のタイミングでもテスト配信できる
4. UI上に「最終実行日時・次回実行予定・実行ログ（直近5件）」を表示

## 4. 成功指標

| 指標 | 内容 |
| --- | --- |
| 定期実行 | APSchedulerのcronトリガーで指定時刻に自動実行できる |
| Flask共存 | BackgroundSchedulerがFlaskサーバーと同プロセス内で動く |
| 手動実行 | ボタン一発でスケジュールと同じ処理を即座に実行できる |
| Discord配信 | 取得した情報をDiscord webhookに整形して送信できる |
| 学習目標 | APScheduler・バックグラウンドスレッド・状態管理の基礎を理解する |

## 5. 対象範囲（スコープ）

### 5.1 対象に含む
- APScheduler BackgroundSchedulerによる定期実行（cronトリガー / JST）
- 配信内容：東京の天気・USD/JPY為替・NHKニュース要約（スプリント#2のfetchers.py再利用）
- Discord webhook への配信
- Webブラウザから配信時刻を設定・保存できる管理UI
- 手動即時実行ボタン
- 直近5件の実行ログ表示（メモリ上）

### 5.2 対象外
- 複数都市・複数通貨ペアの設定
- 配信チャンネルのUI上の変更（webhookURLは.envで固定）
- 実行履歴のDB永続化
- 失敗時のリトライ機構

## 7. 運用フロー

```
APScheduler（バックグラウンドスレッド）
        ↓（指定時刻 or 手動トリガー）
ジョブ関数 run_digest()
        ↓
fetchers.py（天気・為替・ニュース取得 ※TTLキャッシュ付き）
        ↓
Discord webhook（requests.post で整形済みメッセージを送信）
        ↓
実行ログに記録（メモリ上のリスト）
```

Flask は管理UI（ログ表示・手動実行・スケジュール変更）を提供するだけ。
実際の定期実行は BackgroundScheduler が担当。

## 8. 画面構成（UI）

シングルページ構成：

- **ステータスカード**：次回実行予定日時・最終実行日時
- **手動実行ボタン**：「今すぐDiscordに送信」
- **スケジュール設定**：時刻（HH:MM）入力 → 保存ボタン
- **実行ログ**：直近5件をテーブル表示（日時・結果・概要）

## 9. 外部連携・使用技術

| 連携先・ライブラリ | 用途 |
| --- | --- |
| APScheduler（BackgroundScheduler） | Flaskとは別スレッドで定期実行 |
| pytz | JSTタイムゾーン設定 |
| requests | Discord webhook への POST |
| projects/08_api_hub/fetchers.py | 天気・為替・ニュース取得の再利用 |
| Flask | 管理UI提供 |
| Discord Webhook URL（.env） | 配信先チャンネル |

## 10. 非機能要件

| 項目 | 内容 |
| --- | --- |
| スレッド安全性 | 実行ログリストへのアクセスはスレッドロックで保護する |
| エラーハンドリング | ジョブ失敗時はDiscordへのエラー通知ではなくログにのみ記録（配信失敗を配信で通知するのは本末転倒）|
| Render上の動作 | Renderの無料プランはスリープがあるため完全な定期実行は保証できないが、学習目的で許容する |

## 11. 制約事項・前提条件

- `DISCORD_WEBHOOK_URL` と `ANTHROPIC_API_KEY` が `.env` に設定されていること
- pytzはAPSchedulerの依存として自動でインストールされている（別途追加不要）
