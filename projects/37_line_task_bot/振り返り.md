# 振り返り — Project 37: LINE Bot → タスク管理連携

## 発生した課題と解決策

### 1. line-bot-sdk v3のWebhookペイロードに必須フィールドが多い
LINEの実際のWebhookペイロードを模したテスト用JSONを作成する際、最初は
`type`/`message`/`source`/`replyToken`だけを入れていたが、`pydantic`の検証で
`webhookEventId`・`deliveryContext`（イベント全体）、`quoteToken`（テキスト
メッセージ）が必須フィールドとして要求され、これらが無いとパースに失敗して
`UnknownEvent`にフォールバックしてしまい、ハンドラが一切呼ばれなかった。
LINEの公式ドキュメントの実際のWebhookペイロード例を参考に、これらのフィールドを
含めることで解決した。

### 2. APSchedulerのジョブからFlaskのアプリコンテキストを使う
`send_due_reminders()`内でSQLAlchemyの`Task.query`を使うには、Flaskの
アプリケーションコンテキストが必要。`BackgroundScheduler.add_job()`に直接
`send_due_reminders`を渡すと、ジョブ実行時にコンテキストが無くエラーになる。
`with app.app_context(): send_due_reminders()`でラップした関数を別途定義し、
それをジョブとして登録することで解決した。

### 3. LINEのWebhookはHTTPS公開URLが必須で、ローカル単体では実機確認できない
他のOAuth系プロジェクト（Project32のGoogleカレンダー連携）と同様、外部サービスとの
本当の繋ぎ込みにはユーザー自身の操作・環境（本番デプロイ後のURL登録）が必要になる
ケースがある。今回は「署名検証ロジックが正しいこと」を実際にHMAC-SHA256で署名した
テストリクエストで確認することをCode側の責任範囲とし、実際のLINEアプリからの
送受信確認はREADMEに手順を明記してユーザーに委ねた。
