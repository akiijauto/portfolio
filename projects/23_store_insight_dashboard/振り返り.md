# 振り返り — Project 23: 店舗改善インサイトダッシュボード

## 発生した課題と解決策

### 1. データ未入力のままデモを体験してもらうには
**課題:** ポートフォリオとして見てもらう際、実際の店舗データを持っていない人がほとんどなので、
最初から空の入力テーブルだけでは「何を入力すればいいか」が伝わりにくい。

**解決策:** 「サンプルデータを読み込む」ボタンを設置し、クリックすると7日分の売上・客数・
スタッフ人数のデータと、現場メモの例文が一括入力される。そのままAI分析ボタンを押すだけで
ダッシュボードの完成形を体験できるようにした。

### 2. 売上と客数のスケールが異なるグラフ表示
**課題:** 売上（10万円台）と客数（数十人）を同じグラフに表示すると、客数の変化がほぼ見えなくなる。

**解決策:** Chart.jsのデュアル軸（y/y1）機能を使い、売上を左軸、客数を右軸に割り当てた。
右軸はグリッド線を非表示(`grid: { drawOnChartArea: false }`)にして見やすさを確保した。

### 3. AIが断定しすぎないようにする設計
**課題:** これまでのプロジェクト（Project20/21）と同様、データやメモから読み取れない内容を
AIが勝手に補完・創作してしまうと、誤った経営判断につながりかねない。

**解決策:** プロンプトで「データから読み取れない・断定できない内容は無理に記載せず、空文字または
空配列にする」ことを明示。フロント側でも空配列の場合は「該当する項目はありませんでした」と表示し、
存在しない情報をユーザーに誤解させないようにした。

### 4. 改善アクションの優先度表示
**課題:** AIが複数の改善アクションを提案する際、どれから着手すべきか分かりにくい。

**解決策:** improvement_actionsの各項目に「高/中/低」の優先度を持たせ、プロンプトで
優先度の高い順に並べるよう指示。フロント側では優先度ごとに色分けしたバッジ
（高=赤、中=黄、低=緑）で表示し、一覧性を高めた。
